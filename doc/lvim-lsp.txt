1. INTRODUCTION                                             *lvim-lsp-intro*

lvim-lsp is the UI LAYER of the LVIM LSP stack. It drives the lvim-ls engine
(LSP lifecycle, EFM tools, DAP requirements, project resolution) and renders
its panels, forms, info windows and notifications. Tool installation is
delegated to lvim-pkg / lvim-installer — there are no third-party config files
and no mason.nvim dependency (mason-registry is read only when present, for
tool versions in the info window).

Requires lvim-ls (engine) and lvim-utils (UI). The split mirrors lvim-pkg
(engine, zero UI) vs lvim-installer (the UI config holder): lvim-ls.state.config
stays pure data, while the popup / menu / info / project UI config lives in
lvim-lsp.

2. SETUP                                                    *lvim-lsp-setup*
>lua
  require("lvim-lsp").setup({
      file_types = {
          lua_ls = {
              filetypes  = { "lua" },
              lsp        = { "lua-language-server" },
              formatters = { "stylua" },
          },
          rust_analyzer = {
              filetypes = { "rust" },
              lsp       = { "rust-analyzer" },
          },
      },
      server_config_dirs = { "my_config.lsp.servers" },
  })
<
Only `file_types` and `server_config_dirs` are required. Each tool may be a
plain string ("mason-pkg") or a table { "mason-pkg", bin = "binary" } when the
installed binary name differs from the Mason package name.

`setup()` splits the options: UI keys (popup_global, form, menus, project,
info, build/installer, progress appearance, highlights, force) configure
lvim-lsp's own state; everything else (file_types, server_config_dirs,
callbacks, timing, efm, features, code_lens, diagnostics, progress behaviour,
notify, debug, dap_local_fn) goes to the lvim-ls engine.

3. CONFIGURATION                                           *lvim-lsp-config*

Selected options (see README.md for every field and its default):

  on_attach            fun(client, bufnr)  per-client, after attach
  on_dir_change        fun()               after DirChanged
  startup_delay_ms     number              delay before autocmds (100)
  dir_change_delay_ms  number              delay before old servers stop (5000)

  efm.filetypes        string[]            handled even without a tool config
  efm.executable       string              PATH-check binary (efm-langserver)

  features.document_highlight  boolean             CursorHold symbol highlight
  features.auto_format         boolean|fun():bool  format on BufWritePre
  features.inlay_hints         boolean|fun():bool   inlay hints (0.10+)
  code_lens.enabled            boolean             code lens + LspCodeLensRun

  diagnostics.*        vim.diagnostic.config() overrides + sign symbols
  progress.*           enabled / ignore / done_ttl (engine) + appearance (UI)
  notify.*             enabled / min_level / title
  debug.enabled        boolean   file log: stdpath("state")/lvim-lsp/debug.log
  dap_local_fn         fun()|nil  when set, adds the :LvimLsp dap subcommand

UI appearance is controlled by `popup_global` (border, size, keys, icons,
labels), `info`, `installer`, `progress`, `form`, `menus`, `project`, and the
`highlights` / `force` keys. See |lvim-lsp-highlights|.

4. COMMANDS                                              *lvim-lsp-commands*

Everything goes through one entry point: >
  :LvimLsp <subcommand>
<
LSP operations ~
  hover rename format range_format code_action definition type_definition
  declaration references implementation signature_help document_symbol
  workspace_symbol document_highlight clear_references incoming_calls
  outgoing_calls add_workspace_folder remove_workspace_folder
  list_workspace_folders

Diagnostics ~
  diagnostic_current        diagnostics for the current line
  diagnostic_next           jump to next diagnostic
  diagnostic_prev           jump to previous diagnostic

Server management ~
  toggle_servers            enable / disable servers globally
  toggle_servers_buffer     attach / detach servers for the current buffer
  restart                   restart a running server
  reattach                  reattach servers to the current buffer
  info                      open the LSP info window (|lvim-lsp-info|)

Project and installations ~
  project                   per-project settings panel (|lvim-lsp-project|)
  declined                  re-enable previously declined tool installs
  dap                       DAP command (only when `dap_local_fn` is set)

Completion lists every available subcommand.

5. SERVER CONFIG MODULE                                  *lvim-lsp-servers*

Each server is a Lua module found in one of the `server_config_dirs`
prefixes (first match wins), e.g. my_config/lsp/servers/lua_ls.lua: >lua
  return {
      lsp = {
          root_patterns = { ".git", ".luarc.json" },
          config = {                         -- standard vim.lsp.start config
              name = "lua_ls",
              cmd  = { "lua-language-server" },
              settings = { Lua = { diagnostics = { globals = { "vim" } } } },
              on_attach = function(client, bufnr) end,
          },
      },
      efm = {                                -- optional EFM tools
          filetypes = { "lua" },
          tools = {
              { server_name = "stylua", formatCommand = "stylua -", formatStdin = true },
          },
      },
      dap = { adapters = {}, configurations = {} },  -- optional
  }
<

6. PER-PROJECT CONFIG                                    *lvim-lsp-project*

`:LvimLsp project` opens a tabbed panel (Servers / Formatters / Linters /
Filetypes / Global) for the current project root and writes `.lvim-lsp.lua`
to it. The file can also be edited by hand: >lua
  -- .lvim-lsp.lua
  return {
      disable = { "eslint" },     -- servers disabled for this project only
      auto_format = false,        -- override the global feature flags
      inlay_hints = true,
      code_lens = { enabled = true },
  }
<
It is detected automatically on attach. After a manual edit run
`:LvimLsp reattach` to apply immediately.

==============================================================================
7. INFO WINDOW                                              *lvim-lsp-info*

`:LvimLsp info` (or |lvim-lsp-api| `show_info()`) opens a floating window with:
encoding, PID, command and root dir; workspace folders; trigger characters;
a foldable capabilities / settings tick-list; diagnostics per client and per
buffer; attached buffers; Mason package versions (when mason-registry is
present); and EFM linters / formatters per filetype.

==============================================================================
8. INSTALLER                                           *lvim-lsp-installer*

Opening a file whose server needs missing tools triggers lvim-installer's
unified prompt — a tabbed checklist grouped by LSP / DAP / Linter / Formatter
/ Treesitter. Footer buttons (fired by their key):

  a             install all
  s             install only the checked
  c             cancel (install nothing)
  q  <Esc>      quick skip (re-prompting snoozed for 5 minutes)

Skipped packages may then be DECLINED for that filetype — persisted in
lvim-pkg's database and filtered out of every future prompt. Review and
re-enable declines with `:LvimLsp declined`. Completed tools stay visible in
the progress panel for `installer.done_ttl` ms.

9. LUA API                                                   *lvim-lsp-api*
>lua
  local lsp = require("lvim-lsp")

  lsp.missing_for_ft("lua")                 -- missing tools, grouped by server
  lsp.ensure_lsp_for_buffer("lua_ls", bufnr)
  lsp.start_language_server("lua_ls", true) -- force = attach all compatible
  lsp.setup_efm({ "lua" }, { { formatCommand = "stylua -", formatStdin = true } })
  lsp.disable_lsp_server_globally("tsserver")
  lsp.enable_lsp_server_globally("tsserver")
  lsp.disable_lsp_server_for_buffer("tsserver", bufnr)
  lsp.enable_lsp_server_for_buffer("tsserver", bufnr)
  lsp.get_compatible_lsp_for_ft("typescript")   -- → { "tsserver", "efm" }
  lsp.show_info()                               -- open the info window
  lsp.get_state()                               -- snapshot of internal state
  lsp.suppress_progress(true)                   -- pause progress tracking
  lsp.clear_progress()                          -- close the progress panel
  lsp.get_progress_status()                     -- compact statusline string
<

10. HIGHLIGHTS                                        *lvim-lsp-highlights*

All LvimLsp* groups are registered through lvim-utils.highlight from the shared
palette, so they survive a `:colorscheme` change and re-sync when the palette
changes. Override them via the `highlights` key in setup (set `force = true`
to always win over a theme; default: the theme wins).

Info window ~
  LvimLspIcon  LvimLspInfoServerName  LvimLspInfoSection  LvimLspInfoKey
  LvimLspInfoValue  LvimLspInfoConfigKey  LvimLspInfoSeparator
  LvimLspInfoLinter  LvimLspInfoFormatter  LvimLspInfoToolName
  LvimLspInfoBuffer  LvimLspInfoFold

Installer panel ~
  LvimLspInstallerIconPending  LvimLspInstallerIconOk  LvimLspInstallerIconFail
  LvimLspInstallerTool  LvimLspInstallerStatusPending  LvimLspInstallerStatusOk
  LvimLspInstallerStatusFail  LvimLspInstallerAction

Progress panel ~
  LvimLspProgressIcon  LvimLspProgressServer  LvimLspProgressTitle
  LvimLspProgressDone  LvimLspProgressMessage  LvimLspProgressPct

Two further override channels:
  - `info.highlights` remaps each info-window element to any existing group.
  - `popup_global.highlights` overrides lvim-utils LvimUi* colors for THIS
    plugin's popups only (anonymous, scoped — other plugins unaffected).

==============================================================================
11. HEALTH                                                *lvim-lsp-health*

`:checkhealth lvim-lsp` reports the UI layer's prerequisites: Neovim version,
the lvim-ls engine, lvim-utils, the optional lvim-pkg and mason-registry, the
EFM binary, whether `setup()` has run (file_types count), and the active
progress config. The engine's own prerequisites are reported separately by
`:checkhealth lvim-ls`.
