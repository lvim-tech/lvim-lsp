1. INTRODUCTION                                             *lvim-lsp-intro*

lvim-lsp is the UI LAYER of the LVIM LSP stack. It drives the lvim-ls engine
(LSP lifecycle, EFM tools, DAP requirements, project resolution) and renders
its panels, forms, info windows and notifications. Tool installation is
delegated to lvim-pkg / lvim-installer — there are no third-party config files
(mason-registry is read only when present, for tool versions in the info
window).

Requires lvim-ls (engine) and lvim-utils (UI). The split mirrors lvim-pkg
(engine, zero UI) vs lvim-installer (the UI config holder): lvim-ls.state.config
stays pure data, while the popup / menu / info / project UI config lives in
lvim-lsp.

2. SETUP                                                    *lvim-lsp-setup*
>lua
  require("lvim-lsp").setup({
      languages = {
          lua_ls = {
              filetypes  = { "lua" },
              lsp        = { "lua-language-server" },
              formatters = { "stylua" },
          },
          rust_analyzer = {
              filetypes = { "rust" },
              lsp       = { "rust-analyzer" },
          },
      },
      server_config_dirs = { "my_config.lsp.servers" },
  })
<
Only `languages` and `server_config_dirs` are required. Each tool may be a
plain string ("mason-pkg") or a table { "mason-pkg", bin = "binary" } when the
installed binary name differs from the Mason package name.

`setup()` splits the options: UI keys (popup_global, form, menus, project,
info, progress appearance, peek, outline, hover, lightbulb, footers, filters,
highlights, force) configure lvim-lsp's own state; everything else
(languages, server_config_dirs, callbacks, timing, efm, features, code_lens,
diagnostics, progress behaviour, notify, debug, dap_local_fn) goes to the
lvim-ls engine.

TWO WAYS TO DRIVE IT                                        *lvim-lsp-modes*

The engine runs off a CATALOG: which servers exist, for which filetypes, with
which tools (`languages`), and where each server's config module lives
(`server_config_dirs`). It can be filled two ways, and they compose:

  A. STANDALONE — you own the catalog. Pass `languages` + `server_config_dirs`
     to setup() and ship one server-config module per server (the example
     above; module shape in |lvim-lsp-servers|).

  B. THROUGH lvim-lang — providers own the catalog. Leave both at their empty
     defaults; lvim-lang's per-language providers call the additive seam
     `register_language(name, entry, dir_prefix)` (|lvim-lsp-api|), which
     APPENDS `entry` to `languages` and `dir_prefix` to `server_config_dirs`,
     so servers/tools appear as you open files — nothing hard-coded in setup: >lua
        require("lvim-lsp").setup({})   -- languages = {}, server_config_dirs = {}
        require("lvim-lang").setup({})  -- providers register dartls, gopls, … on open
<
The two modes COEXIST: a standalone catalog and lvim-lang providers can run
side by side — each register_language() extends what setup() started with, and
`unregister_language(name)` removes one cleanly when a provider is replaced.

3. CONFIGURATION                                           *lvim-lsp-config*

Selected options (see README.md for every field and its default):

  on_attach            fun(client, bufnr)  per-client, after attach
  on_dir_change        fun()               after DirChanged
  startup_delay_ms     number              delay before autocmds (100)
  dir_change_delay_ms  number              delay before old servers stop (5000)

  efm.filetypes        string[]            handled even without a tool config
  efm.executable       string              PATH-check binary (efm-langserver)

  features.document_highlight  boolean             CursorHold symbol highlight
  features.auto_format         boolean|fun():bool  format on BufWritePre
  features.inlay_hints         boolean|fun():bool   inlay hints (0.10+)
  code_lens.enabled            boolean             code lens + LspCodeLensRun

  diagnostics.*        vim.diagnostic.config() overrides + sign symbols
  progress.*           enabled / ignore / done_ttl (engine) + appearance (UI)
  notify.*             enabled / min_level / title
  debug.enabled        boolean   file log: stdpath("state")/lvim-ls/debug.log
  dap_local_fn         fun()|nil  when set, adds the :LvimLsp dap subcommand

UI appearance is controlled by `popup_global` (size, keys, icons, labels),
`info`, `progress`, `form`, `menus`, `project`, `peek`, `outline`, `hover`,
`lightbulb`, and the `highlights` / `force` keys. The frame border is the single
shared lvim-utils `config.ui.border` (no per-plugin override). See
|lvim-lsp-highlights|.

4. COMMANDS                                              *lvim-lsp-commands*

Everything goes through one entry point: >
  :LvimLsp <subcommand>
<
The navigation subcommands accept an optional layout arg: >
  :LvimLsp <feature> [native|area|float|bottom]
<
overriding the global `peek` knobs for that one call (native = Neovim's built-in
handler; area/float/bottom = the lvim-utils picker layout). See |lvim-lsp-peek|.

LSP operations ~
  hover rename format range_format code_action definition type_definition
  declaration references implementation signature_help document_symbol
  workspace_symbol outline outline_focus document_highlight clear_references
  incoming_calls outgoing_calls add_workspace_folder remove_workspace_folder
  list_workspace_folders

Feature toggles ~
  toggle_inlay_hints        toggle inlay hints for the buffer (Neovim 0.10+)
  toggle_codelens           toggle CodeLens for the current buffer

Diagnostics ~
  diagnostic_current        interactive float for the line (|lvim-lsp-diagnostic|)
  diagnostic_next           walk to the next diagnostic, show it in the float
  diagnostic_prev           walk to the previous diagnostic, show it in the float
  diagnostics               two-pane diagnostics navigator (|lvim-lsp-peek|)

Server management ~
  toggle_servers            enable / disable servers globally
  toggle_servers_buffer     attach / detach servers for the current buffer
  restart                   restart a running server
  reattach                  reattach servers to the current buffer
  info                      open the LSP info window (|lvim-lsp-info|)
  log                       open the debug log in a read-only split

Project and installations ~
  project                   per-project settings panel (|lvim-lsp-project|)
  declined                  re-enable previously declined tool installs
  dap                       DAP command (only when `dap_local_fn` is set)

Completion lists every available subcommand.

                                                           *lvim-lsp-peek*
Location peek ~

The navigation commands (definition / type_definition / declaration /
references / implementation / incoming_calls / outgoing_calls /
workspace_symbol / document_symbol / diagnostics) render results through the
lvim-utils picker / peek — a location list grouped by file plus a live preview.
It is controlled by these global knobs under `peek`: >lua
  peek = {
      native = false,   -- false = lvim-utils picker/peek (default); true = built-in handlers
      layout = "area",  -- "area" (msgarea zone, default) | "float" | "bottom"
      dock_stack = true, -- true = managed dock-stack entry; false = standalone open
      force = { float = {}, area = {}, bottom = {} }, -- per-layout geometry overrides
      appearance = { ... }, -- forwarded to the lvim-utils picker/peek
  }
<
native/layout are overridable PER CALL — through the API
(`require("lvim-lsp").definition({ layout = "float" })`) or a command arg
(`:LvimLsp definition native`). A single location result always jumps directly.
List keys: j/k move, <CR> open, <C-x> split, <C-v> vsplit, q close. (The list has
a live query input, so the jump keys are chords — letters go into the filter.)

When `dock_stack = true` (default) the peek joins the shared dock stack as ONE
entry (glyph = `peek.appearance.icon`): one visible per layout (never overlapping
a docked picker / terminal), cyclable with <Leader>n / <Leader>p, closable with
<Leader>x, listed in <Leader>m — its menu name following the current peek's
title. Set `dock_stack = false` to open the peek standalone (still centrally
sized/backdropped, outside the stack).

`force` overrides the peek geometry per layout, deep-merged over the global
lvim-utils dock geometry (empty {} inherits it). Each layout may carry height,
height_auto, backdrop = { enabled, mode, dim = { amount }, darken = { amount } },
auto_hide, keep_focus; float ALSO width / width_auto. area and bottom are always
full-width, so their width / width_auto are ignored.

Diagnostics navigator ~

`:LvimLsp diagnostics` opens the same picker over diagnostics: every diagnostic
grouped by file (each row with its severity sign) on the left, a live preview on
the right. Centred under the title, a filter bar carries a scope toggle
([W]orkspace / [B]uffer) and a severity filter ([A]ll [E]rror [W]arn [I]nfo
[H]int); press a button's bracketed letter (scope Shift+W / b, severity
a e w i h), click it, or press f to cycle severity — all re-filter live, each
button showing its count. Each file header's `[count]` takes the active filter's
colour; a filter with no matches shows a "No <Filter> diagnostics" message (in
that colour) and clears the preview, instead of a blank list.
`:LvimLsp diagnostics native` falls back to vim.diagnostic.setqflist().

                                                      *lvim-lsp-diagnostic*
Diagnostic float ~

`:LvimLsp diagnostic_current` (and `diagnostic_next` / `diagnostic_prev`) open an
interactive float for a line's diagnostics — the house chrome shared with the
hover. Each is `message  (source)` (message in its severity colour, source dim),
most severe first, the count in the title. A `➤` marks the selection:
`diagnostic_current` lands on the most severe; next / prev WALK every individual
diagnostic in document order (line -> severity -> column), so arriving at a line
lands on its error and several at one position are each visited (told apart by
their message). Press <CR> to focus, then j/k or n/p to move the selection (the
editor cursor follows); q closes; a manual move dismisses it. The one window is
reused as you navigate (re-rendered + repositioned in place, no flicker). The
float HUGS the content (never pads wider than the message), growing only up to
`max_width` (a fraction of the screen when <= 1, else absolute columns). Tune the
marker, padding and cap: >lua
  diagnostics = {
      marker = { enabled = true, icon = "➤", pad = { 1, 1 }, bg_tint = 0.3 },
      text_pad = { 1, 1 },
      max_width = 0.8,
  }
<

                                                           *lvim-lsp-hover*
Hover ~

With `hover = { enabled = true }`, `:LvimLsp hover` renders the documentation in
a themed float (house chrome, markdown-rendered) instead of the built-in popup.
It opens unfocused; press the trigger key again to focus and scroll it.

                                                         *lvim-lsp-outline*
Document Symbols outline ~

`:LvimLsp outline` toggles a persistent side-split outline panel that lists the
current file's symbol tree and follows the cursor; `:LvimLsp outline_focus`
opens it (if needed) and focuses it. It is a real split window (native <C-w>
navigation), docked on `outline.position` at `outline.width` of the editor.

  follow=true       highlight the symbol under the source cursor
  auto_fold=true    accordion: keep only the current symbol's ancestors open
  auto_close=false  close the panel after jumping to a symbol
  fold_initial      "none" (all expanded) | "all" (all collapsed)
  detail=true       show each symbol's detail/signature as dim virtual text
  source_colors     colour names/icons from the buffer's own highlights

Panel keys (all under `outline.keys`, all configurable): <CR> jump (honours
auto_close), <S-CR> jump + close, o peek (move source cursor, stay), <C-g>
restore, <C-j>/<C-k> next/prev + peek, h/l/<Tab> fold/unfold/toggle,
W/E/<S-Tab> for all, R reset, A resume auto-fold, <C-space> hover, a code
actions, r rename, g? cheatsheet, q/<Esc> close. See |lvim-lsp-config| /
README for every field.

5. LIGHTBULB                                           *lvim-lsp-lightbulb*

With `lightbulb.enabled = true` (the default), a 󰌵 hint appears on the cursor
line whenever an attached client offers a CODE ACTION there — virtual text
(a soft yellow chip right after the line's text; `placement = "virtual_text"`)
or a sign-column glyph (`placement = "sign"`). With `show_preferred = true` the
accent raises yellow → orange when any offered action is marked isPreferred.
>lua
  lightbulb = {
      enabled = true,
      placement = "virtual_text",  -- "virtual_text" (EOL chip) | "sign"
      icon = "󰌵",
      update_ms = 150,             -- debounce (ms) after the last cursor event
      only = nil,                  -- CodeActionKind filter, e.g. { "quickfix", "refactor" }
      show_preferred = true,       -- orange accent when an action isPreferred
  }
<
Updates are debounced (`update_ms`) on CursorHold / CursorMoved in normal mode;
the previous in-flight request is cancelled before the next is issued and a
late response for an older cursor position is dropped. The hint clears on
InsertEnter, on leaving the buffer, when the result is empty, and when the
last codeAction-capable client detaches. `only` narrows the probe to the given
CodeActionKinds (forwarded as context.only) so ubiquitous source / format
actions do not light it constantly; nil = all kinds.

Per-buffer opt-out (e.g. large generated files): >lua
  vim.b.lvim_lsp_lightbulb_disable = true
<
For statusline / winbar consumers,
`require("lvim-lsp").get_lightbulb(bufnr)` returns `{ count, preferred }` —
the availability at the last completed probe (`{ count = 0 }` when the buffer
is not lightbulb-attached).

6. SERVER CONFIG MODULE                                  *lvim-lsp-servers*

Each server is a Lua module found in one of the `server_config_dirs`
prefixes (first match wins), e.g. my_config/lsp/servers/lua_ls.lua: >lua
  return {
      lsp = {
          root_patterns = { ".git", ".luarc.json" },
          config = {                         -- standard vim.lsp.start config
              name = "lua_ls",
              cmd  = { "lua-language-server" },
              settings = { Lua = { diagnostics = { globals = { "vim" } } } },
              on_attach = function(client, bufnr) end,
          },
      },
      efm = {                                -- optional EFM tools
          filetypes = { "lua" },
          tools = {
              { server_name = "stylua", formatCommand = "stylua -", formatStdin = true },
          },
      },
      dap = { adapters = {}, configurations = {} },  -- optional
  }
<

7. PER-PROJECT CONFIG                                    *lvim-lsp-project*

`:LvimLsp project` opens a tabbed panel (Servers / Formatters / Linters /
Filetypes / Global) for the current project root and writes `.lvim-lsp.lua`
to it. The file can also be edited by hand: >lua
  -- .lvim-lsp.lua
  return {
      disable = { "eslint" },     -- servers disabled for this project only
      auto_format = false,        -- override the global feature flags
      inlay_hints = true,
      code_lens = { enabled = true },
  }
<
It is detected automatically on attach. After a manual edit run
`:LvimLsp reattach` to apply immediately.

==============================================================================
8. INFO WINDOW                                              *lvim-lsp-info*

`:LvimLsp info` (or |lvim-lsp-api| `show_info()`) opens a floating window with:
encoding, PID, command and root dir; workspace folders; capabilities tick-list;
diagnostics per client and per buffer; attached buffers; Mason package versions
(when mason-registry is present); EFM linters / formatters per filetype; and the
full Server Capabilities / Settings (nested).

Every section is a fold, COLLAPSED by default — a closed section shows its header
plus a hidden-line count. <CR> toggles the section under the cursor; the footer
carries `zM` collapse all, `zR` expand all, `q` close. The hardware cursor is
hidden (the active row reads via the cursorline).

==============================================================================
9. INSTALLER                                           *lvim-lsp-installer*

Opening a file whose server needs missing tools triggers lvim-installer's
unified prompt — a tabbed checklist grouped by LSP / DAP / Linter / Formatter
/ Treesitter. Footer buttons (fired by their key):

  a             install all
  s             install only the checked
  c             cancel (install nothing)
  q  <Esc>      quick skip (re-prompting snoozed for 5 minutes)

Skipped packages may then be DECLINED for that filetype — persisted in
lvim-pkg's database and filtered out of every future prompt. Review and
re-enable declines with `:LvimLsp declined`. Installation progress is rendered
by lvim-installer itself (lvim-lsp only triggers the prompt).

10. LUA API                                                   *lvim-lsp-api*
>lua
  local lsp = require("lvim-lsp")

  -- Navigation (keymap-friendly). Each takes an optional { native?, layout? }
  -- overriding the global peek knobs for that call.
  lsp.definition()  lsp.type_definition()  lsp.declaration()
  lsp.references()   lsp.implementation()
  lsp.incoming_calls()  lsp.outgoing_calls()
  lsp.workspace_symbol()  lsp.document_symbol()
  lsp.diagnostics()  lsp.hover()  lsp.outline()

  -- Additive catalog seam (|lvim-lsp-modes| B — the seam lvim-lang uses):
  -- append `entry` to `languages` + `dir_prefix` to server_config_dirs, then
  -- attach to open buffers of its filetypes. Callable after setup.
  lsp.register_language("gopls", { filetypes = { "go" }, lsp = { "gopls" } }, "my_plugin.servers")
  lsp.unregister_language("gopls")          -- inverse: stop + drop from the catalog

  lsp.missing_for_ft("lua")                 -- missing tools, grouped by server
  lsp.ensure_lsp_for_buffer("lua_ls", bufnr)
  lsp.start_language_server("lua_ls", true) -- force = attach all compatible
  lsp.setup_efm({ "lua" }, { { formatCommand = "stylua -", formatStdin = true } })
  lsp.disable_lsp_server_globally("tsserver")
  lsp.enable_lsp_server_globally("tsserver")
  lsp.disable_lsp_server_for_buffer("tsserver", bufnr)
  lsp.enable_lsp_server_for_buffer("tsserver", bufnr)
  lsp.get_compatible_lsp_for_ft("typescript")   -- → { "tsserver", "efm" }
  lsp.show_info()                               -- open the info window
  lsp.get_state()                               -- snapshot of internal state
  lsp.suppress_progress(true)                   -- pause progress tracking
  lsp.clear_progress()                          -- close the progress panel
  lsp.get_progress_status()                     -- compact statusline string
  lsp.get_attached_status(bufnr)                -- "lua_ls, efm  E1 W2" (statusline)
  lsp.get_lightbulb(bufnr)                      -- { count, preferred } (|lvim-lsp-lightbulb|)
<

11. HIGHLIGHTS                                        *lvim-lsp-highlights*

All LvimLsp* groups are registered through lvim-utils.highlight from the shared
palette, so they survive a `:colorscheme` change and re-sync when the palette
changes. Override them via the `highlights` key in setup (set `force = true`
to always win over a theme; default: the theme wins).

Info window ~
  LvimLspIcon  LvimLspInfoServerName  LvimLspInfoSection  LvimLspInfoKey
  LvimLspInfoValue  LvimLspInfoConfigKey  LvimLspInfoSeparator
  LvimLspInfoLinter  LvimLspInfoFormatter  LvimLspInfoToolName
  LvimLspInfoBuffer  LvimLspInfoFold

Progress panel ~
  LvimLspProgressIcon  LvimLspProgressServer  LvimLspProgressTitle
  LvimLspProgressDone  LvimLspProgressMessage  LvimLspProgressPct

Code-action lightbulb ~
  LvimLspLightbulb  LvimLspLightbulbPreferred  (sign column, yellow / orange)
  LvimLspLightbulbVirtualText  LvimLspLightbulbVirtualTextPreferred
  (EOL chip — the accent fg on a soft 0.15 bg tint of itself)

Document Symbols outline panel ~
  LvimLspOutlineWinbar  LvimLspOutlineName  LvimLspOutlineDetail
  LvimLspOutlineGuide  LvimLspOutlineFold  LvimLspOutlineCursor
  LvimLspOutlineKindFunc  LvimLspOutlineKindType  LvimLspOutlineKindIface
  LvimLspOutlineKindVar  LvimLspOutlineKindField  LvimLspOutlineKindConst
  LvimLspOutlineKindModule  LvimLspOutlineKindValue  LvimLspOutlineKindObject
  LvimLspOutlineKindMisc

Diagnostics peek filter bar ~
  LvimLspPeekFilter{Sev}  LvimLspPeekFilter{Sev}Active
  LvimLspPeekFilter{Sev}HoverActive  (Sev = Error|Warn|Info|Hint)
  LvimLspPeekFilterScope  LvimLspPeekFilterScopeActive
  LvimLspPeekFilterScopeHoverActive  LvimLspPeekFilterAllHoverActive

Two further override channels:
  - `info.highlights` remaps each info-window element to any existing group.
  - `popup_global.highlights` overrides lvim-utils LvimUi* colors for THIS
    plugin's popups only (anonymous, scoped — other plugins unaffected).

12. HEALTH                                                *lvim-lsp-health*

`:checkhealth lvim-lsp` reports the UI layer's prerequisites: Neovim version,
the lvim-ls engine, lvim-utils, the optional lvim-pkg and mason-registry, the
EFM binary, whether `setup()` has run (languages count), each configured
server with missing tools, the currently running clients, the active progress
config, and the lightbulb state (enabled / placement / debounce / kind
filter). The engine's own prerequisites are reported separately by
`:checkhealth lvim-ls`.
